# §6. Suggestions

Part of the [data dictionary](../data-dictionary.md) — see it for the ERD, the **Conventions** that
govern every domain, and the routing table. Cited elsewhere as **data dictionary §6**.

> **Storage codes:** `REL` relational · `TS` time-series (Timescale hypertable) · `VEC` vector.
> **Traces** cites the requirement (`R-#`), ADR, or `gh#N` the row answers to.

| Entity | Key fields | Storage | Traces |
|---|---|---|---|
| **Suggestion** | **account** (the parent whose mode the R-14 guard compares against — gh#7 made the account linkage explicit), instrument, direction, entry, stop, target(s), size, confidence, validity window, strategy, rationale (signals cited), version / supersedes, **lifecycle state** (active / stale / expired-void), **state-changed-at** (gh#545), mode — **mode-guarded like Order** (constraint trigger + mode ≠ `undeclared` CHECK: nothing is ever suggested on an undeclared account). **Implemented — journal spine** (gh#7): account FK, instrument, side/size, entry/stop/target, mode, state (≠ unknown CHECK), createdAt. **First issuer** (gh#402): the **agent-review** trigger route stages an `Active` suggestion when its reviewer proposes one — **account + size from the trigger** (never the model), direction / entry / stop / target from the (gated-below-model, geometry-validated) proposal, **mode read live from the account** (so the `enforce_mode_matches_account` guard never trips), and the venue-neutral **symbol** in `Instrument` (front-month resolves at take-time, exactly as an order does). **Issuance fields landed** (gh#542/#543/#544): the LLM-authored **rationale** is now **persisted** — it was previously generated, billed and discarded, and the older claim that it was *"surfaced + traced"* was never true (nothing logged, traced or displayed it). It is capped at 2000 chars **at the reviewer's parse boundary**, so an over-long rationale fails closed rather than being truncated into a misleading journal entry, and it is **untrusted display data** — never re-injected into a later prompt, and specifically never carried into the gh#476 deep-review enrichment. The **cited signal** rode with it as a nullable `TriggerFiringId` **plus copied** `CitedIndicator` / `CitedPeriod` / `CitedResolutionMinutes`. **The multi-cited-factor model landed** (gh#729, ADR-0026): those three columns are **dropped** and the citation is now a **`CitedFactor` set** (see its row) — N factors, exactly one flagged **primary** (the smallest-timeframe, gh#592's `min` rule), the rest supporting; the single-cited-signal case is the **N=1** "set of one" the `AddSuggestionCitedFactors` migration backfills every existing suggestion into. **The headline timeframe is the primary factor's** (gh#592): a fully-specified suggestion states the bar size it is framed on (scalp vs swing, R-4), surfaced as a first-class **`TimeframeMinutes`** the read model reconstructs from the primary factor — still **no duplicate column**. The *supporting* factors (multi-timeframe corroboration + aligned price levels, held as R-4-immutable **snapshots** of gh#595's mutable levels) are now **assembled at issuance** (gh#730); gh#729 shipped the model + the level-reference shape + N=1 issuance. **`Confidence`** (0–100, range CHECK) is asked for in **both** reviewer schemas and validated fail-closed (missing or out-of-range ⇒ `MalformedOutput` ⇒ no suggestion); it is **display only** — a zero-confidence proposal still becomes a row and `Size` still comes from the operator's trigger, so the model cannot self-censor by number. **`ExpiresAt`** (CHECK `> CreatedAt`) is the **system's** value: `min(configured validity, time to this market's auto-flatten deadline)`, so a suggestion can never outlive the flatten about to close the position; the migration backfills existing rows to `CreatedAt + 1 second` — already expired (fail-safe) while satisfying the strict inequality. **First reader** (gh#540): a suggestion was **write-only** until the read model landed — `GET /accounts/{id}/suggestions` (defaults to the actionable `Active` set, newest first, page size capped by `SuggestionReadOptions`) and `GET /suggestions/{id}` (**any** state, so the journal stays readable after a row expires). Both are ordinary request paths, so the automatic R-20 filter applies and **neither uses `IgnoreQueryFilters`** — a stranger gets an empty list and a **404** by id, never a disclosure that the row exists. The response projects the spine plus a derived **reward:risk ratio** (`|target − entry| / |entry − stop|`, null when risk is zero — the read model never divides by zero on a row it did not write) and deliberately omits `UserId`, which is always the caller. **Dollar risk/reward** rides alongside it (gh#541), money-valued server-side from the instrument's configured contract spec via the single shipped `InstrumentSpec.LossPerContract` seam; both are **null when the instrument has no configured spec** — a display figure degrades rather than being guessed, whereas the take path must refuse outright. Indexed `(UserId, State, CreatedAt)` for that query shape. **The state / disposition boundary is settled** (gh#539), because `expired` previously appeared on *both* sides and nothing said which owned it: **`SuggestionState` is system-driven** — the clock and the market move it (`active → stale → expired-void`), and **`SuggestionDisposition` records operator acts only** (`taken` / `modified` / `passed`). So **nothing writes an `expired` disposition**: the expiry sweep advances `State` and writes **no** disposition row, because a system timeout is not an operator act and forging one would let a background pass fabricate decision history. *"Expired without action"* is therefore **derived**, not stored — `State = ExpiredVoid` **and** no disposition row — which is the shape R-9 unions over. **Implemented — the expire writer** (gh#545): the **first production code to write a non-`Active` state**. One pure `SuggestionLifecycle.Decide(state, expiresAt, now)` (Domain — `SuggestionState` moved here from the data layer, mirroring `ConditionalStatus`) is the semantic authority for both a **time-driven steady-state sweep** (`SuggestionExpiryHost`) and the **startup recompute** (run in `StartupTasks` *before* the rehydrator counts, so a suggestion that expired while the process was down is voided, not reported active — the recovery catch-up is the first sweep, not a separate path); both run **one guarded writer** (`ISuggestionExpiry`) whose SQL predicate mirrors it. It moves a past-window **live** suggestion (`Active` **or** `Stale`) to `ExpiredVoid`, stamping the new nullable **`StateChangedAt`** audit column **atomically** in the same write, through a **guarded one-way conditional update** (`ExecuteUpdate WHERE State IN (Active, Stale)` — monotonic `Active → Stale → ExpiredVoid`, so a concurrent drift/supersede/take writer cannot clobber it; **not** a symmetric EF concurrency token). It is **forward-only and idempotent** (a returned price never un-expires a row) and **no-risk** — an expired suggestion never enters the rehydration consistency verdict (`DecisionSurfaceReport.ExpiredOnRecovery` is a count, never an inconsistency). No migration for the state (the `<> 0` CHECK admits it); `StateChangedAt` is a nullable add. **Version / supersedes landed** (gh#550): a re-formed setup issues a **superseding** suggestion rather than mutating or resurrecting one — `Version` (int, default 1, both a CLR initializer and the DB default) + a self-referencing `SupersedesId` (`Guid?`, `OnDelete: Restrict`, so a superseded row can never be deleted and the R-9 lineage never silently vanishes; migration `AddSuggestionSupersede`, additive). In the scan's `StageSuggestionAsync`, a **non-terminal (`Active`/`Stale`), undispositioned** incumbent for the **same trigger + instrument + side** — keyed on the originating firing's `TriggerId`, **not** the symbol, so different indicators / periods on one symbol stay distinct rather than voiding each other — is voided (reusing `ExpiredVoid`) and the new row issued with `Version = incumbent.Version + 1` and `SupersedesId = incumbent.Id`, all **in the scan pass's shared transaction**. Single-incumbent is enforced **in application code, not a partial unique index** — an index violation would abort that shared `SaveChanges` and lose the firing journal + arm transition (the gh#455 pattern). The incumbent's **trade parameters are never mutated** — only its lifecycle state. A **side-flip** re-arm (opposite side, same trigger) issues an *independent* row, not a supersede (the key includes side). The read model returns the **head of the chain** by default (a superseded row is `ExpiredVoid`, excluded by the `Active` default) while any row stays readable by id. **Implemented — the take path arms an order** (gh#548, *part A*): `POST /suggestions/{id}/take` is the **first path that turns a suggestion into an order** — it **arms** an editable `Staged` `Order` (see §4) through the order compose ladder **minus transmission** and **refuses** anything not currently takeable: non-`Active`, past its window **re-checked against the clock via the same `SuggestionLifecycle.Decide`** the sweep uses (so a not-yet-swept row is still caught, R-12), already dispositioned (409), **already backing a live order** (409 — a defensive anti-stacking guard from the gh#548 review, so a double-click on Approve cannot mint two `Staged` tickets off one suggestion for the gh#589 send-vs-take gap to transmit; a cancelled / rejected / filled order frees it, the taken-forever semantic being part B's disposition), another operator's (404), an instrument with **no configured spec** (fail-closed — `InstrumentSpec` never client-supplied), or one whose price has **drifted past `Suggestions:DriftToleranceTicks × tick` re-measured now** (the synchronous drift re-check, ahead of the eventually-consistent `Stale` flag the gh#546 consumer will write). The **size is the suggestion's** (never re-derived), the catastrophic **safety stop is derived** from entry ± the spec's `SafetyStopTicks × tick` with its `safety → working → entry` ordering pre-checked in code (the arm writes no `StopPlan`, so `CK_StopPlans_SafetyBeyondActual` never sees it — this guard is the only backstop), the gate is **untouched and still resizes/blocks**, and the arm stamps `Order.SuggestionId`. Sending stays the existing gated endpoint. The **`taken` / `modified` disposition + deviation recording is part B** (gh#549) — an arm writes **no** disposition. **Implemented — the drift writer** (gh#546): the **middle** lifecycle state finally has its writer — a **third `market.quote` consumer** (`SuggestionDriftHost`, sibling of the gh#545 expire sweep and the gh#153/#198 quote consumers) that moves an `Active` suggestion to `Stale` once price has **drifted past the entry tolerance**, so a scratched setup greys out **before** execution, not only at take time. The decision is a new pure `SuggestionLifecycle.HasDrifted(side, entry, bid, ask, tolerance)` — **symmetric** distance from the *achievable* entry (a long measures the **ask**, a short the **bid**), exclusive boundary matching the take-time re-check, deliberately unlike the conditional order's directional cancel-band. The write is the guarded, forward-only `ISuggestionDrift` update — `ExecuteUpdate WHERE State == Active` (Active-only, so idempotent and race-free against the sweep's `IN (Active, Stale)`; the same monotonic `Active → Stale → ExpiredVoid` chain, **not** an EF concurrency token) — stamping `StateChangedAt` in the same write; the band is `Suggestions:DriftToleranceTicks × tick` (**the same band the gh#548 take-time re-check uses**). Because a quote carries the venue **contract key** while a suggestion stores only the **neutral symbol** (and there is no reverse lookup — the front month rolls), the consumer is **symbol-driven**: it resolves each distinct `Active` symbol **forward** to its front-month key **once per pass** (never per quote) and matches the batch. **Cannot measure ⇒ no transition** (R-4): no configured spec, or a venue that cannot resolve this pass, leaves the row `Active` (the take-time synchronous re-check is the backstop); a retention gap needs no backfill (the next quote re-checks). **No migration** — `Stale` was always admitted by the state CHECK, and the read model already surfaces it: `State == Stale` **is** the reason (with `StateChangedAt` for the *when*), and the default `Active`-only list excludes it while `?state=Stale` and by-id keep it readable, so the card greys out with no schema change. **Embedded for retrieval** (gh#1065, R-6): the deferred VEC half now exists — the embedding pass writes an `OwnerKind = Suggestion` row (§10) keyed by the suggestion's id, over its **trade line + rationale**; the **state** is deliberately not in that text, so a lifecycle transition never re-bills a paid re-embed. It is **owner-scoped** (R-20): the vector store is global, so retrieval reads the suggestion back through the tenant filter and another operator's row is simply absent. Retrieved rationale stays **untrusted display data** — it reaches a chat turn as user-role grounding, never the system prompt, which is the same rule that already forbids re-injecting it into the gh#476 deep-review enrichment. **A second producer landed (gh#1134):** the chat `generate_suggestion` tool stages a row on operator request, so a `Suggestion` is no longer necessarily the scan's. Such a row is identifiable by `TriggerFiringId IS NULL` with `Version = 1` and `SupersedesId IS NULL` — chat cites no firing and opens its own chain rather than joining a trigger's supersede spine, which is keyed on a firing's trigger identity it has none of, and it carries **no `CitedFactor` set** (the N=0 case: nothing fired, so nothing is cited). Every other column is the system's exactly as on the scan's path — `Size` from `Suggestions__ChatProposalSize`, `Mode` read live off the account (so `enforce_mode_matches_account` holds), `ExpiresAt` from the configured window clamped to the flatten deadline — and `State` is `Active`, **never** dispositioned: staging is not taking, and the R-4 issuance throttle deliberately does not apply (it is a scan policy over unprompted issuance). **Deferred:** strategy (A5 gh#19 owns the `Strategy` entity) | REL + VEC | R-4, R-6, R-8 |
| **SuggestionDisposition** | suggestion, disposition kind, **pass reason(s)** + note, ts. **Vocabulary settled** (gh#539) ahead of the writers (gh#547 pass, gh#549 take), so two cards cannot mint two enums. **Kind is operator acts only — `taken` / `modified` / `passed`.** `expired` is **not** a disposition: see the state-vs-disposition boundary below. Kind carries the refusable `Unknown = 0` + a `<> 0` CHECK (the shipped `CK_Suggestions_State_NotUnknown` pattern). **Pass reasons are the canonical eight** — *already positioned · news risk · wrong time · waiting / better level · weak R:R · sizing · against a rule · low conviction* — taken from the operator-validated pass sheet in the wireframes; PRD R-4's earlier list was introduced with *"e.g."* and was **illustrative, never exhaustive**, so this canonicalises rather than overrides it. Stored as a **`[Flags]` column plus a length-capped note**: multi-select in one integer, sliceable by R-9 with a bitwise test, and a child table buys nothing for a single-operator deployment. **The reason column's zero is legitimate and must NOT get a `<> 0` CHECK** — a pass is a *neutral decline* and its reason is explicitly optional (R-4), so "no reason given" is a real, valid answer; only `Kind` is refusable-zero. **One disposition per suggestion**, enforced by a unique index — matching the ERD above, which already draws `Suggestion \|\|--\|\| SuggestionDisposition`. It is **append-only journal evidence**: a second disposition **conflicts** rather than overwriting, and a disposition never mutates the suggestion's trade parameters. **Implemented — the pass writer** (gh#547): the entity ships (`Kind` + `Reasons` `[Flags]` + optional `Note` capped at 1000 + `CreatedAt`, FK to `Suggestion` cascade, **unique** `IX_SuggestionDispositions_SuggestionId`, and only the `CK_SuggestionDispositions_Kind_NotUnknown` check — the `Reasons` column deliberately carries none), and **`POST /suggestions/{id}/pass`** writes the `passed` disposition — reasons and note both optional, a pass on **any** lifecycle state accepted (the note is worth keeping past the window), a second pass **409-conflicts**, and a dispositioned suggestion **drops out of the default actionable list** while staying readable by id and under an explicit-state filter. **Implemented — the take writer** (gh#549): a successful send of a suggestion-armed ticket writes the `taken` disposition when the submitted parameters match the suggestion, or `modified` with the **recorded deviations** when they do not — a `SuggestionDeviation` `[Flags]` (entry / stop / target / size; `None = 0` is valid and carries **no** `<> 0` CHECK, exactly like `Reasons`) plus a take-time **snapshot** (`TakenEntryPrice`, `TakenStopPrice` — the **working** protective stop, not the safety stop, gh#134 — a **nullable** `TakenTargetPrice` since a take may legitimately drop the target, and `TakenSize`). The **size snapshot is the operator-armed size**, captured **before** the gate's approved quantity overwrites `Order.Size`, so a gate reduction is never misread as an operator deviation; the comparison is **exact on the persisted decimals** — no tolerance may silently record a modified take as taken (R-9 integrity) — and is computed once by the pure `SuggestionDisposition.ForTake` so every reader shares one verdict. Two DB backstops below the model land with it: `CK_SuggestionDispositions_Deviations_MatchModified` (deviations non-empty **iff** `Kind = Modified`) and `CK_SuggestionDispositions_TakeSnapshot` (a `taken` / `modified` row carries entry + stop + size, a `passed` row carries none; `TakenTargetPrice` is exempt on the take side). The write is journaled in its **own** save **after** the order's `Working` flip has committed in `OrderEndpoints` — both the take-success block and the stranded-take **reconcile-adopt** recovery (gh#589) — so it can **never** abort a take that is **live at the venue** (the gh#455 pattern). This matters because the one-per-suggestion unique index has a writer the take is **not serialized against** — a concurrent `pass` on the same suggestion takes no account lock — so were the disposition part of the order's transaction, that race would roll a live take back; a pre-check keeps the common already-disposed case clean, and the losing insert is **caught and skipped** (a missing deviation record is the recoverable gap the design accepts over a rolled-back live take). A direct (non-suggestion) ticket writes none. The read model surfaces it on `GET /suggestions/{id}` (a nullable `Disposition` with its deviations + snapshot, the *suggested* values staying on the suggestion so the client renders the wireframe's *was → now* delta per field), and the one-per-suggestion rule now holds **both ways** — a taken suggestion can no longer be passed. Migration `AddSuggestionDispositionDeviations` is additive (`Deviations` defaulted 0; four nullable snapshot columns) | REL | R-4, R-8, R-9 |
| **MarketSnapshot** | suggestion, condition snapshot at issuance (indicators, order-flow, price, news refs) | REL / VEC | R-8 |
| **CitedFactor** | suggestion (FK, cascade), **`Kind`** (indicator / level, refusable-zero), **`IsPrimary`**, **`TimeframeMinutes`**, an **indicator arm** (`Indicator` / `Period`) **or** a **copied level-snapshot arm** (`LevelId` soft-ref + `LevelVenue` / `LevelKind` / `LevelTop` / `LevelBottom` / `LevelSignificance`). **Implemented** (gh#729, ADR-0026): the **cited-factor set** a suggestion carries — N factors with **exactly one primary** (the smallest-timeframe, gh#592's `min` rule; the pure `CitedFactorSet.DerivePrimary` picks it, so issuance never hand-sets the flag) and zero-or-more supporting. **N=1 is the degenerate "set of one"** every suggestion is today; the `AddSuggestionCitedFactors` migration **backfills** every existing suggestion into one primary Indicator factor and **drops** the Suggestion's old `Cited*` columns (single source of truth per the ADR). A cited level is a **snapshot, not an FK** to `PriceLevel`: that entity is **mutable** (merges, flips, retires), and **R-4 needs the citation immutable once issued**, so the level's `Kind` / band / significance are **copied** at issuance and never track the live level. **`IUserOwned`** (operator-owned, not a global). DB backstops mirror the domain: `Kind <> 0`, `TimeframeMinutes > 0`, a **kind/columns pairing** CHECK (an indicator factor carries the indicator arm and a null level arm; a level factor the reverse), `LevelTop > LevelBottom` when present, and a **partial unique index** `(SuggestionId) WHERE IsPrimary` backstopping "at most one primary" (the "at least one" stays app-enforced — the gh#455 shared-transaction pattern, an index abort would lose the firing journal). **The read model** reconstructs the old `CitedIndicator` / headline `TimeframeMinutes` from the primary factor, so the API + SPA stay back-compatible. **Assembly landed** (gh#730): the *supporting* factors are now populated at issuance — the pure `ConfluenceAlignment.AlignSupporting` (ADR-0026 §3) corroborates the fired signal against the **same indicator on other timeframes** and **levels whose zone the entry sits within `min(k ticks, f×ATR)`** of (the tick arm alone when ATR is unmeasurable), appending each as a supporting factor (indicator arm, or a copied level snapshot). `DerivePrimary` ranks the **indicator** factors alone, so the fired signal stays primary and a **level is never primary**. **Fail-open** — a confluence read fault degrades to the N=1 set, never aborting the scan pass | REL | R-4, gh#593, ADR-0026 |
