> **Traces** cites the requirement (`R-#`), ADR, or `gh#N` the row answers to.

| Entity | Key fields | Storage | Traces |
|---|---|---|---|
| **Embedding** | owner type + id (suggestion / rule / soft-signal / snapshot / **topic**), vector, model (Cohere), created ts **Implemented** (gh#109, migration `AddEmbeddingStore`) as `EmbeddingRecord` / table `Embeddings`. Keyed on **owner kind + owner id + model** — model is IN the key because vectors from different models are not comparable, and the key doubles as the idempotence guard so a re-embed **updates** rather than appends (embedding is a paid call; re-ingestion is normal). Carries `Dimensions` and a `ContentHash` so an unchanged owner is recognised and the paid re-embed skipped. `vector(1024)` (Cohere embed-v3), **HNSW cosine** index. **Global / not `IUserOwned`** (R-20), following its owners. **Relational-only in the EF model** — `Vector` has no in-memory mapping, so coverage is integration-tier. **Skipped entirely where pgvector is unavailable** (gh#109 degrade: the app still starts, trading is unaffected, and the absence is declared rather than silent) — and since gh#474 the provider actually reports unavailable, so no embed is paid for a vector with nowhere to go. Providers: the keyless default ships here, Cohere in gh#403; first consumer gh#377. **Nearest-N read seam (gh#852, R-2):** retrieval ranks by `CosineDistance` (cosine distance in `[0,2]`; similarity = `1 - distance`) over the HNSW cosine index — `INewsEmbeddingSimilarity.NearestNewsAsync` = `.Where(OwnerKind = SoftSignal).OrderBy(CosineDistance).Take(n)` — behind `NewsSemanticSearch`, which embeds the **query** with input type `search_query` (the write path embeds documents as `search_document`) and **degrades to an empty result** when the provider is unavailable, the query does not embed, or the read faults, so a consuming feed falls back to its non-semantic axis and never errors. **Salience counterpart (gh#853, R-2/R-9):** `INewsEmbeddingSimilarity.GetVectorsAsync` reads back the stored `SoftSignal` vectors for a set of owners (a plain `Where(OwnerKind = SoftSignal).Where(ownerIds.Contains(OwnerId))` read, **no** `CosineDistance`), and `SemanticSalienceAxis` ranks the feed's **window candidates** in-process by **max cosine similarity** to the operator's **starred** vectors (nearest single star, clamped `[0,1]`) via the pure `EmbeddingSimilarity` helper — feeding the news feed's `SemanticEmbedding` axis (ADR-0014) and degrading to an empty axis on the same unavailable/fault conditions. Scoring the **known window candidates** (not a global nearest-set) is what keeps a recent near-a-star item from being starved, and it is two bounded reads, not one query per star. The vector **read** is relational-only like the write path, so `NearestNewsAsync` is **proven by QA #855** and `GetVectorsAsync` by a **paired QA card**, while the ranking math is **pure and unit-tested**. **Topic-match counterpart (gh#854, R-2):** the same polymorphic store gains an **`OwnerKind = Topic`** owner kind with **no migration** — the `OwnerKind` integer column's only constraint is `<> 0` and the PK `(OwnerKind, OwnerId, Model)` + indexes already admit any owner kind. The news-embedding pass also embeds each `NewsTopic` (name + keywords, keyed by topic name) as a `Topic` row against the **same** provider, per-pass spend tally and ledger; `INewsEmbeddingSimilarity.GetTopicVectorsAsync` reads them back — the topic analogue of `GetVectorsAsync`, a plain `Where(OwnerKind = Topic)` read — so the relevance pass matches a news vector to a topic vector in-process via the same pure `EmbeddingSimilarity` helper (kept a distinct seam method, not an owner-kind parameter, so the Domain seam carries no `Data` enum).
