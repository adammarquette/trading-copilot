# §12. Chat & audit

Part of the [data dictionary](../data-dictionary.md) — see it for the ERD, the **Conventions** that
govern every domain, and the routing table. Cited elsewhere as **data dictionary §12**.

> **Traces** cites the requirement (`R-#`), ADR, or `gh#N` the row answers to.

| **Conversation / ChatMessage** | role, content, tool invocations, grounding refs, ts — persists across sessions. **Persistence foundation implemented** (gh#18 inc 1, migration `AddChatConversations`): entity `Conversation` (`Id`, nullable `Title` ≤256, `CreatedAt`, `UpdatedAt`) and `ChatMessage` (`ConversationId` FK → **cascade**, `Sequence` 1-based, `Role` = `ChatRole` User/Assistant/System, `Content` ≤32768, `CreatedAt`), **both `IUserOwned`** (R-20 — a message carries its **own** `UserId`, so a *direct* `ChatMessages` query is scoped too, not only reads that join through the conversation). Reads: conversations `(UserId, UpdatedAt)` most-recent-first; messages by the **unique** `(ConversationId, Sequence)` index — the in-order read **and** the ordering-integrity guard. **DB CHECKs** (fail-closed-zero): `Role <> 0`, `Sequence > 0`. Gives **gh#471** the `Conversation` its trigger-origin audit references. **REST CRUD implemented** (gh#18 inc 2): the `/conversations` surface — `POST /conversations` create (optional `Title` ≤`TitleMaxLength` 256), `GET /conversations` list (**most-recent-first**, clamped page size), `GET /conversations/{id}` the conversation + its messages **in `Sequence` order**, and `POST /conversations/{id}/messages` append — all **R-18 authenticated, R-20 owner-scoped** (a foreign/absent conversation is a **404**, never a disclosure). Two write guards carried from inc 1's review: a message's **`UserId` is the conversation's**, read under R-20, **never request input** (`AppendMessageRequest` carries only `Role` + `Content`, no owner); and `Sequence` is allocated **`max+1`** with the unique index as the backstop — a lost race is a **409** (the `max+1` read is not itself race-free; the index is what keeps the thread integral). `Role` fails closed (`Unknown`/undefined → **400**), `Content` required + ≤`ContentMaxLength` (**400**), `Title` ≤ cap (**400**). New **"Chat"** OpenAPI group (drift-guard allow-list). **Grounded chat turn implemented** (gh#18 inc 3, gh#906): `POST /conversations/{id}/turns` — appends the operator's `User` turn, runs the model over the thread under a **fixed** co-pilot system prompt (holds **no risk limits or account state** — enforcement lives below the model, the LLM only proposes), and appends the `Assistant` reply. **Governor-gated** before the call (gh#448 daily AI-spend budget, deployment-wide windowed read via `IgnoreQueryFilters`, **fail-open** on a read fault so a bookkeeping blip never pauses the co-pilot; **429** when the day's budget is reached, nothing persisted); the call is **metered** (export-only) **+ ledgered** (`AiUsageFeature.Chat`, durable, **fail-open**) whatever its outcome, so the governor floor sees every billed call (a tool-using turn bills several, gh#925); **fail-closed** on a refused / truncated / faulted turn (**422**, the user turn stays saved, **no assistant turn invented**). The reply is pushed **per-owner over the hub** (`realtimeChatMessage`, **presentation-only** per **ADR-0021** — the REST turn response already carries it) and returned over REST. **Token streaming implemented** (gh#919 inc 3b): the reply is also pushed **token-by-token as it generates** — `ILlmProvider.StreamAsync` (real Server-Sent-Events on the Anthropic client, **fail-closed** exactly as `CompleteAsync`) drives a **`realtimeChatChunk`** per delta to the owner **during** the call, per-owner + **fail-open** (a dropped chunk never aborts the turn); the final `realtimeChatMessage` and the REST response stay the source of truth (ADR-0021). `Content` stays **untrusted display data** — it rides as a `User` / `Assistant` turn, **never folded into the system prompt** as instruction. **Tool invocations (inc 4, gh#925, ADR-0025):** the chat turn now offers **read-only** tools (`get_quote` / `query_journal`) the model calls in a **bounded** loop — `ILlmProvider` maps `tool_use` rather than failing closed on it, and each loop call is its own `AIUsage` row; the model can never place/size an order (read-only by construction). **Always-on grounding implemented (inc 5, gh#995, ADR-0027; cross-kind since gh#1065):** every turn now also retrieves a little reference material for the operator's message — **news**, plus the operator's own **suggestions** and **journal entries** (closed trades) — through the shared read-only `IContextRetrievalService` (one query-embed → a recall **per kind** → hydrate → merge nearest-first → **one** rerank, §10 — the `search_news` pipeline, now shared rather than a second copy; that tool still asks for news only). The owner-scoped kinds are **R-20 scoped at the hydrate** — the §10 vector store is deployment-global, so a recalled row belonging to another operator is simply absent from the read and dropped. It places what it found as **untrusted user-role content** behind a fixed *"data, not instructions"* envelope on the operator's **final `User` turn** — **never** the fixed system prompt (an injection sentinel in a retrieved item can never become an instruction, exactly the posture message `Content` has; **empty grounding is byte-identical** to an un-grounded turn). It rides the turn's **single** governor gate — retrieved **after** the gate passes and the user turn is persisted, **skipped** once spend crosses the pre-alert threshold (grounding bills an extra embed + rerank, so it is the first cost shed as the cap nears), and **fail-open** (any retrieval fault degrades to a history-only turn) — and its **embed (`Embed`) + rerank (`Chat`) spend is ledgered fail-open** stamped to the operator (the §10 AIUsage floor the next turn's windowed read sees). Grounding is **ephemeral per turn** — rebuilt from the live feed each turn and **persisted nowhere** (no `ChatMessage` column, **no migration**), so the audit trail records that a turn happened, never the transient reference material it saw. **Deferred:** **rulebook** grounding (epic gh#15 has not started, so there is no rule entity to embed); proactive follow-ups; the chat SPA surface | REL (grounding is ephemeral — reads §10 VEC, persists none) | R-6 |
| **AuditRecord** | actor, action (order / guardrail / kill / flatten / **connection-loss**), **placement (native / synthetic / none)** + **`source`** (operator / guardrail / dead-man's switch / scheduler — what tripped a safety action) + **`synthetic_risk`** (a live position resting on an in-app synthetic stop / bracket — an **orphan risk** if the connection drops), before → after, ts — immutable. **Implemented — the connection-loss lifecycle** (gh#220): entity `AuditRecord` (table `AuditRecords`), **operator-owned** (R-20, `IUserOwned` — a row is invisible to any other operator), append-only. The orphan guard (gh#209/gh#191) writes one row per synthetic-stop transition — `Hidden → Orphaned` on a drop, `Orphaned → Hidden` (re-arm) or `Orphaned → Retired` on reconnect — each `action = connection-loss`, `placement = synthetic`, `synthetic_risk = true`, stamped with the affected stop's **owner** and its **plan id** (a *soft* reference — no FK, so the immutable trail survives the stop it records). A **secondary, failure-tolerant** write: the safety action commits first, then the audit; an audit-store failure is logged and swallowed, **never** failing the guard (proven by a test that makes the write throw). **DB CHECKs** mirror the fail-closed-zero convention: `action ≠ unknown`, `placement ≠ unknown`; indexed `(user, ts)` for the chronological read. **Further write sites landed:** the **OCO-exit retire** (gh#183, `action = position-exit`) and an **order-cancel** (gh#250, `action = order-cancelled` — an operator cancel via the API **or** a venue-detected cancel / rejection reconciled by the account-event stream) each write a row **when a stop plan is retired** — a flat-position / never-filled-entry cleanup, so **not** `synthetic_risk`. An **order-modify** (gh#259, `action = order-modified`) writes a row on an operator **reprice** of a working order — `before → after` carries the entry-price transition; a never-filled resting entry, so likewise **not** `synthetic_risk`. A **resize** (gh#292) writes the same `order-modified` action with `before → after` carrying the **size** transition (and the `Detail` spelling out any entry / working-stop move that rode with it). **Kill-switch & auto-flatten landed (gh#765):** every kill-switch **engage** and **disengage** (`action = kill-switch-engaged / -disengaged`) and every executed-or-escalated **auto-flatten** (`action = auto-flatten`, `after` = `Flat` / `Escalated` / `Missed`) now writes an immutable row, carrying the new **`source`** (`operator` today; the guardrail / dead-man's-switch seams named for when they land) — so the kill-switch **history survives beside** the single mutable `KillSwitchState` row a re-engage used to overwrite. These are account/system actions resting on no single protective leg, so `placement = none` and no `synthetic_risk`; the owner is the operator (a kill) or the affected account (a background flatten). **Two** new CHECKs join the two existing fail-closed ones (migration `AddAuditSourceForKillAndFlatten`): **`source ≠ unknown`** (null-tolerant — the stop-plan actions carry no source), and a **`source ↔ action`** correlation enforced *below the model* — a safety action (kill / flatten, 5 / 6 / 7) MUST carry a source and a stop-plan action (1–4) MUST leave it null (`CK_AuditRecords_Source_MatchesAction`). Both remain **secondary, failure-tolerant** writes, exactly like the guard's. **R-15 outcome hard-delete landed (gh#909):** a confirmed **hard delete** of a journal `Outcome` (§7) writes one row — a new **`action = outcome-hard-deleted`** (value 8, outside the 5–7 safety set, so **`source` is null** per `CK_AuditRecords_Source_MatchesAction`; `placement = none`, no `synthetic_risk`) whose `Detail` names the removed outcome and its resolution, so the **fact** of the deletion outlives the content (R-15). Owned by the outcome's operator, the same secondary failure-tolerant write (the removal commits first). Applies to **both** kinds since gh#955: a hard delete of either a trade-derived or an untaken outcome writes an `OutcomeSuppression` tombstone the journal sweeps anti-join, so the removal sticks and its `outcome-hard-deleted` row is genuinely durable (at gh#909 a trade-derived outcome was instead **refused**, since the writer would recompose it). **Deferred:** the **guardrail** write site (the trigger lands with it) and the **real-time operator alert** (gh#222 — a high-severity log carries `synthetic_risk` for now) | REL | eng §9, ADR-0007, ADR-0013 |
| **AIUsage** | invocation: feature (suggestion / follow-up / backtest / triage / embed), model + tier, tokens in/out, **est. $ cost**, latency, trace id, ts, **user** — spend tracking + governor input. **Implemented** (gh#431, migration `AddAiUsageLedger`) as `AiUsageRecord` / table `AiUsage` — the per-call spend ledger, `IUserOwned` (R-20), append-only. Shipped fields: `Feature` + `Outcome` (both **refusable-zero** enums with `<> 0` CHECKs — `Outcome` distinguishes Succeeded / Refused / Truncated / **Failed** / RateLimited), `Model` (≤128) + nullable `Tier`, `InputTokens` / `OutputTokens` / `EstimatedCostUsd` (`numeric(18,8)`) / `LatencyMs` (all `>= 0`), nullable `TraceId` (≤64, W3C, ADR-0002), and `OccurredAt` (**caller-supplied** — the ledger reads no clock); indexed `(user, occurredAt)`; **seven** DB CHECKs. The **agent-review reviewer** is the first recorder (`Feature = Triage`); cost is priced **once per call** from its `LlmUsage` at a **single pinned per-tier rate** (`LlmOptions` — $1/$5 Triage, $3/$15 Deep). A fire records **one row per LLM call**: a single Triage row normally, and — when the triage **escalates** (gh#449) — a **second Deep-tier row** (still `Feature = Triage`, since `Tier` is the spend-distinguishing dimension; the escalated triage row is `Succeeded`). The two rows are non-atomic (a host death between them records only the first — consistent with the floor caveat below). **Fail-open, and a FLOOR not a complete accounting:** the write runs in its **own** owner-scoped context (not the caller's transaction) and a fault is logged + swallowed at **both** the ledger *and* the scan boundary, so a bookkeeping blip can never roll back a fire — but nothing is recorded if the host dies between the call and the write, so the **spend governor** (gh#448) **enforces on this floor**: the aggregate meter (ADR-0002) proved `System.Diagnostics.Metrics` **export-only** (Prometheus, not app-readable), so it cannot reconcile against it in-process — reconciliation is operator-side in Grafana and the effective cap is the budget plus at most one in-flight **call** — the triage→deep **pair** overrun (gh#449) is **closed by gh#478**: the scan checks a conservative deep-call estimate against the remaining budget and withholds the escalation (`EscalationDeclined`) when it would not fit, so a fire can no longer pass the pre-call gate and then spend both tiers. The governor's **read** is a **deployment-wide daily windowed `SUM`** of `EstimatedCostUsd` via `IgnoreQueryFilters` (all owners **and** the `SystemOwner` embed rows — the R-20 filter is crossed only here), on the Central trading-day; the budget is **deployment config** (`GovernorOptions`), not a persisted entity (no schema change). A **`Failed` row carries zero tokens** — billable latency the governor must see, a real datapoint, not an absence. **Embed-path attribution settled (gh#436):** a **global** embed's row (embedding deployment-global news / snapshots, gh#377) is owned by the deployment **`SystemOwner`** sentinel — *not* the operator (keeping infra spend out of the per-decision meter) and *not* `Guid.Empty` — with `Feature = Embed`, `Tier` null, `OutputTokens` 0, and `Outcome` mapped from `EmbeddingOutcome` (a 429 degrade-to-sparse → `RateLimited`); **the live producer landed (gh#377):** `NewsEmbeddingService` ledgers one row per attempted embed — success or failure alike — via the existing scoped `IAiUsageLedger` (no new write path), and gates each call on the same shared daily budget. Surfaced two ways: aggregated in **Grafana** (ADR-0002) for the operational view — **now live for both halves** (the LLM-side meter landed, gh#477: `ai.llm.{calls,input_tokens,output_tokens,cost_usd,latency}` by model / tier / outcome on the same `MarqSpec.TradingCopilot.Ai` meter, fed the same per-call `AiCallCost` in the scan, so Grafana shows true total AI spend, LLM + embed — export-only, so it does **not** change the governor's ledger-floor read); and **read back in the app** for the spend meter (gh#62). The **aggregate** in-app read **landed (gh#741)**: `GET /api/ai/spend` returns the period **total + by-day + by-model** as the operator's **own decision spend** (R-20 owner-scoped — the SystemOwner embed rows excluded), plus **today's spend deployment-wide** against the daily cap (`GovernorOptions.DailyBudgetUsd`, on the Central-trading-day window the governor enforces — read `IgnoreQueryFilters` so *today vs cap* is exactly what pauses the co-pilot, embed spend included). Reads the durable ledger, never the export-only meter (ADR-0002). Surfaced as the settings **AI usage & spend** section (U3 gh#25). **Per-suggestion attribution — the correlation landed (gh#767, migration `AddAiUsageTriggerFiringId`):** a nullable **`TriggerFiringId`** (soft link, matching `Suggestion.TriggerFiringId` — no FK, so the fail-open ledger outlives the trigger it references; filtered index `(user, TriggerFiringId) WHERE TriggerFiringId IS NOT NULL`) now stamps the **firing** each agent-review call served. It is the per-suggestion cost key: the cost is ledgered *before* the suggestion is staged, so the firing — which the `AIUsage` row **and** the `Suggestion` both carry — is the only key that spans them; an escalated fire stamps **both** the triage and deep rows. Chat and embed calls serve no firing and carry `null`. The **read surface landed (gh#767 inc B):** `GET /api/ai/attribution` returns, over a period and **R-20 owner-scoped**, each **suggestion's** total cost (its firing's rows summed, with the call count so a triage→deep escalation reads as `Calls > 1`), each **taken trade's** cost against its realized outcome (`Trade.SuggestionId → Suggestion.TriggerFiringId → Σ cost`), and the **unattributed** spend of billed reviews that produced no suggestion (the orphan-firing bucket — surfaced, never dropped, so Σ per-suggestion is a *floor* on agent-review spend). Reads the ledger, never the meter (ADR-0002). X1 gh#26 owns the metric. The spend is the operator's own, billed to their own keys (ADR-0015) | REL | ADR-0008, ADR-0002, Q-10 |
