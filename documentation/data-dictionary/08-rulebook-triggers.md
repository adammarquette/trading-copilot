# §8. Rulebook & triggers

Part of the [data dictionary](../data-dictionary.md) — see it for the ERD, the **Conventions** that
govern every domain, and the routing table. Cited elsewhere as **data dictionary §8**.

> **Storage codes:** `REL` relational · `TS` time-series (Timescale hypertable) · `VEC` vector.
> **Traces** cites the requirement (`R-#`), ADR, or `gh#N` the row answers to.

| Entity | Key fields | Storage | Traces |
|---|---|---|---|
| **Rule** | intent text, structured form, enabled, source conversation, confirmed, **`instrument_dependency_snapshot`** (the Instrument / RelevanceConfig metadata the rule resolved against **at confirmation**), **`needs_revalidation`** — if that metadata later changes (symbol reclassified, topic remapped) the rule is **flagged for review** so a stale trigger can't fire on the wrong asset | REL + VEC | R-7 |
| **Trigger / Condition** | compiled condition, route (**mechanical-alert / agent-review**), debounce / rate-limit, enabled, source rule. **Implemented — mechanical route** (gh#385): `TriggerRecord` (IUserOwned, R-20) carries an **indicator-threshold** condition (indicator / period / resolution / **comparison** / threshold + optional **hysteresis** dead-band, over the R-22 store), `Route` (**mechanical** + **agent-review** both built — gh#385 / gh#402), `Severity`, `Enabled`, a **`Confirmation`** {Unconfirmed → Confirmed} gate (gh#470) that is **distinct from `Enabled`** — a newly authored trigger is **Unconfirmed** and therefore inert *regardless of `Enabled`*, and the scan evaluates only **Confirmed** triggers, so authorship (including an agent-proposed one) arms nothing until the operator's separate **`POST /{id}/confirm`**; the **3-state debounce** (`ArmState` {Unseeded → Armed → Fired} + `ArmCycle`) that fires **once** on the arming edge and re-arms on the opposite (a level + edge = a cross; a null indicator holds — fail-closed), nullable **`SourceRuleId`** and **`SourceConversationId`** — the R-7 provenance seams (soft refs, no FK) to the rule that authored the trigger and the conversation it came from, both surfaced on the read path so a trigger's origin is answerable without a query (gh#471) — **`SourceConversationId` now has a writer** (gh#1135): the chat `edit_rulebook` tool (§12, R-6/R-7) authors and amends triggers from a conversation and stamps it, while `SourceRuleId` stays null until the `Rule` entity (gh#866) exists. A chat-authored trigger is **`Mechanical`, `Enabled` and `Unconfirmed`** — inert until the operator's own confirm, which is what makes model authoring safe rather than the tool's restraint — carries **no `AccountId` or `Size`** (chat alerts, it never issues a sized suggestion), and is refused by exactly the checks `POST /api/triggers` makes, now shared as `TriggerAuthoring` rather than copied. An **amend returns the trigger to `Unconfirmed`** and re-seeds `ArmState`/`ArmCycle` just as `PATCH` does, and never touches `Route`, `AccountId` or `Size` — but only when it actually applies a change (gh#1155): naming an identity field (symbol / indicator / period / resolutionMinutes — changing one is authoring a different rule, not editing this one), sending a present-but-wrong-typed value (a string where a number belongs, previously misread as absent), or naming no amendable field at all is **refused** rather than reported as `"amended"`, and none of them touch `Confirmation`, `ArmState` or `ArmCycle` — and, for the **agent-review** route, a nullable **`AccountId`** (FK, cascade) + **`Size`** (both required by that route, DB-checked; a mechanical trigger carries neither). A periodic **`TriggerScanHost`** (aligned to the indicator cadence) reads the indicator, applies the pure `TriggerDebounce`, and on a crossing dispatches on route: **mechanical** *sends a mechanical alert* through `INotificationChannel` (**send-before-commit**); **agent-review** (gh#402) *wakes the reviewer* (behind `ILlmProvider`; a genuinely-hard setup escalates to a second **deep-tier** call — gh#449 — which the scan **enriches** with a **bounded numeric market-context** read — recent OHLCV bars + the fired indicator's recent values, **as of the fire**, over the **global** R-1 / R-22 projections, rendered deep-only inside a data fence — gh#476, a **transient read model, no new table** and no schema change), and on a proposal **stages a `Suggestion`** + an advisory (**commit-then-notify**), on a suppress does neither — either way it **notifies / proposes, never places an order** (enforcement stays below the model — the review path reaches no order/venue/gate type). The reviewer's LLM call is served by the real **`AnthropicLlmProvider`** once a key is present (gh#423); the stub stands in only when unconfigured. The reviewer's per-call token / cost / latency is recorded to the **`AIUsage`** ledger (gh#431, §12) — **one row per LLM call** (two on an escalation, gh#449), stamped with the **firing owner** (the scan is the single tenancy authority), fail-open. **Deferred:** the NL → condition compiler (R-7), order-flow (R-3) / composite / cross-asset / time conditions, a wall-clock rate-limit (`LastFiredAt` seam shipped). Ten DB CHECKs mirror the refusable-zero enums + positivity + the route/account pairing + the `Confirmation` known-value check (gh#470) + the **per-indicator `Threshold` range** (gh#1007, `CK_Triggers_Threshold_InIndicatorRange`): a threshold is validated against the indicator's own semantics — **rsi ∈ (0, 100)** (bounded oscillator, so a value at or beyond a bound makes one inclusive direction always- or never-true) and **atr > 0** (a non-negative magnitude) — because a permanently-satisfied condition (e.g. `rsi at-or-above 0`) seeds the debounce straight to `Fired` and holds it there, **ADR-0019's silent monitor reached from authoring** rather than by drift; refused by name at `POST`/`PATCH` (`TriggerThreshold`) and backstopped below any writer by the CHECK, added `NOT VALID` so a row authored before the gate does not fail the deploy. **A dependency outage is now visible** (gh#469): holding fail-closed on a null indicator was always correct but silent — a trigger whose dependency stopped being produced (symbol out of `Ingestion:Symbols`, a changed resolution, an indicator no longer in `IndicatorSet`) simply never fired, and *"the condition never occurred"* was indistinguishable from *"unevaluable for a week"*. `UnmeasurableSince` records when the current run of unevaluable readings began (null = measurable), so **duration** separates a late bar from a broken trigger; past 30 minutes the scan logs a warning naming the trigger and the missing indicator, **once** rather than every pass -- which needed a second column, `StalenessReportedAt`, to actually be true (gh#515: the first cut tested only the elapsed threshold, which stays crossed, so it warned on every poll -- roughly 1,440 lines per trigger per day). Both columns clear together on recovery, so a later outage is a new incident. It **never disables the trigger** — a pipeline hiccup must not silently disarm an alert. Nullable with no default, so existing rows start clean rather than being back-dated into an outage the migration cannot know about. Same posture as the ATR band (gh#311), which likewise refuses to promote and warns | REL | ADR-0008, R-4/R-7, R-22 |
| **TriggerFiring** | the trigger layer's **append-only firing journal** (gh#385): trigger, fired-at, **observed value**, threshold, comparison, **dedup key** (`trigger:{id}:{armCycle}` — a distinct incident per crossing, stable within an armed episode). IUserOwned (R-20). This is the layer's durable record of what fired; **no `AuditAction` is minted** for it — a mechanical alert touches no order or position, so it does not belong in the order/synthetic-risk audit schema | REL | ADR-0008, R-4 |
