# §9. Non-market / soft signals

Part of the [data dictionary](../data-dictionary.md) — see it for the ERD, the **Conventions** that
govern every domain, and the routing table. Cited elsewhere as **data dictionary §9**.

> **Storage codes:** `REL` relational · `TS` time-series (Timescale hypertable) · `VEC` vector.
> **Traces** cites the requirement (`R-#`), ADR, or `gh#N` the row answers to.

News is the reference template; other non-market feeds reuse this shape (R-2).

| Entity | Key fields | Storage | Traces |
|---|---|---|---|
| **SoftSignal (NewsItem)** | source, type (news / social / …), published + crawl ts, title, content, url, tickers, **matched instruments / topics** (relevance), tags, **dedup key**, **provenance (source feeds[])**; sentiment **deferred**. **Implemented** (gh#358, migration `AddNewsStore`) as `NewsRecord` / table `News` — the deduped **store of record** for R-2 ingestion, the news analogue of `BarRecord`: the **`DedupKey`** (a canonicalized URL, `NewsDedupKey`) is the **primary key and idempotence guard**, so the same story from Finnhub *and* Tiingo collapses to one row (their feeds union into **`SourceFeeds`**) and an overlapping re-poll updates in place, never duplicating. When the two feeds carry it under **different** URLs (canonical links rarely agree), an R-2 **fuzzy fallback** (title similarity + published-time window + ticker overlap, `NewsFuzzyDedup`, gh#764) collapses a **truncated / extended re-headline** — one title's content a superset of the other's — unioning provenance **and tickers** rather than storing a duplicate; ticker overlap is **required**, so it never merges on title + time alone and a false merge cannot silently destroy a distinct signal. The fallback is **cross-feed only**, within a pass and across passes alike (gh#1129 / gh#1132): a near-duplicate headline under a new URL from a feed already carrying the story is a follow-up or correction — a distinct row — never a merge target, so a same-feed HashSet-style no-op union can't silently drop it. An **arbitrary rewording** (each side rephrasing the other) stays two rows — the safe over-count — pending the **semantic** (`pgvector`) path (gh#377). **Global / not `IUserOwned`** (R-20), like the bars; the per-user salience that reweights it (`SoftSignalFeedback`, gh#27) is a separate entity. **Shipped fields:** `DedupKey`, `Type`, `Url`, `Title`, `Summary`, `PublishedAt`, `Tickers` (raw, un-mapped), `SourceFeeds`, `RecordedAt`. **Now resolved:** the relevance **`MatchedInstruments` / `MatchedTopics`** are materialized onto the row by gh#359. Staleness is decided by a **monotonic `RelevanceVersion`** (gh#418) — the config generation the row was resolved against — not a wall clock; `RelevanceResolvedAt` remains as an observability timestamp only. **Deferred:** the **`pgvector` embedding** — the `VEC` half — (gh#377, with the Cohere path gh#103), plus sentiment (R-2) and tags | REL (+VEC gh#377) | R-2, R-20 |
| **NewsTopic** | name, tags / keywords / embedding, scope (instrument \| global). **Implemented** (gh#359, migration `AddNewsRelevance`) as `NewsTopic` — **global deployment config**: `Name` (unique), `Keywords[]`, `Scope` (Instrument \| Global — a refusable zero), `Instrument?` (for an instrument-scoped topic). **Now semantic (gh#854):** alongside keyword matching, a topic's **embedding** — its name + keywords, embedded on the **same pass as news** and stored as an `EmbeddingRecord` with **`OwnerKind = Topic`** (no schema change: the polymorphic `VEC` store absorbs the new owner kind) — lets a news item match a topic by **cosine proximity** of the news vector to the topic vector, **additive** to keywords and degrading to keyword-only when the embedding provider or the `pgvector` read is unavailable. The read is proven by a paired QA card (§10) | REL (+VEC gh#854) | R-2 |
| **RelevanceConfig / TopicMap** | ticker↔instrument maps (SPY→ES), per-instrument topics, global topics; **AI-suggested + user-curated** (config panel); **personalized importance weights** learned from `SoftSignalFeedback` stars (per-dimension salience multipliers, ADR-0014). **Implemented** (gh#359) as `TickerInstrumentMap` (key `(Ticker, Instrument)`) + `NewsTopic` + a single-row `RelevanceConfigState` carrying a **monotonic `Version`** (gh#418). The base maps + topics are **global deployment config** — SPY→ES is a market fact, not an operator preference — so not `IUserOwned`; the **per-user salience weights** are the operator-owned part (gh#27). A 60s pass resolves matches onto the (global) news; a config edit **increments `Version`** so any news below it re-resolves — a counter, not a timestamp, so the decision has no clock-skew or edit-mid-pass window (gh#418, replacing the gh#359 `UpdatedAt < RelevanceResolvedAt` comparison). **Deferred:** AI-suggested mappings (needs the A-loop). **Semantic (embedding) topic match is now live (gh#854)** — a news vector matched to a topic vector by cosine proximity, additive to the keyword path. | REL | R-2, R-6/R-7, ADR-0014 |
| **SoftSignalFeedback** | per-user feedback on a soft-signal / news item: **kind** (**important / star** \| sentiment 👍/👎 \| **mute**), value / weight, ts, **user**; a **star** raises the personalized **salience** of similar future items — a **soft signal, never a risk control**; transparent + adjustable (un-star / mute, salience floor). **Implemented** (gh#27, migration `AddSoftSignalFeedback`) as `SoftSignalFeedback` — **operator-owned** (`IUserOwned`, R-20): `Kind` (**Star** \| **Mute** for the **importance** axis, **ThumbsUp** \| **ThumbsDown** for the **direction** axis — a refusable zero), `NewsDedupKey` (the rated item), `CreatedAt`. **Two independent axes (gh#762)** — importance (magnitude → salience) and direction (👍/👎 → R-9 learning) — each hold **at most one row per operator per item**, but **independently**, via **two filtered unique indexes** over `(UserId, NewsDedupKey)` (one per axis, `"Kind" IN (1,2)` and `"Kind" IN (3,4)`; migration `AddSoftSignalDirectionAxis`, correcting the gh#27 single index that would force one axis to overwrite the other). Re-rating **replaces within its axis** and leaves the other untouched; clearing deletes only that axis's row. **Direction is salience-inert** — it feeds R-9 learning + the `/api/news` read surface (with an explainable reason), and is **excluded from the salience profile**, which still accumulates star/mute alone — so a 👍/👎 never reweights what surfaces. Salience is **computed on read** by `/api/news`: a per-dimension (**instrument / topic / source**), **recency-decayed** (exponential half-life, default 14 d) profile aggregates the operator's stars/mutes into a **multiplier on base relevance**, clamped to a **floor > 0** (a muted item is down-weighted, never hidden) and a cap, with an explainable **"why weighted"** reason. **A soft salience weight only** — structurally unreachable from the risk gate (ADR-0007; a unit guard asserts no `Domain.Risk` type references `Domain.Signals`, and QA #362 asserts a maximally-starred/muted signal leaves a gate outcome byte-identical). **Now active (gh#853):** the **semantic-embedding** dimension — an item's stored embedding scored by **max cosine similarity** to the operator's **starred** items' embeddings (nearest single star), mapped to a `[0,1]` weight and folded into the same clamped multiplier; it **degrades off** (empty axis) when the embedding provider or the `pgvector` read is unavailable, and its real read is proven by a paired QA card (data dictionary §10). **Deferred:** the named-entity dimension (gh#377) degrades off; the **subagent sentiment classifier** (cheap-model, R-2 — the operator 👍/👎 **direction** rating shipped first as the free, R-9-feeding half, gh#762) | REL | R-2, R-6, R-9, ADR-0014, ADR-0017 |
